# 专题归档与周报关联

把证据工作台产出的专题保存到本地，再按需导出公开论文目录。周报通过 DOI 或 AMiner ID
显示“专题概览”链接，方便从新推荐回到已有专题。此阶段不自动生成综述结论，也不重新读取
原文核验传入证据包的引用判断。

## 1. 本地归档

先按 [证据工作台](research-dossiers.md) 生成 `evidence-ledger.json`。在项目目录运行：

```powershell
python -m src.research_archive import --dossier "<已有证据包目录>"
python -m src.research_archive list
```

默认写入 `data/research-archive/r_<内容哈希>/`，该路径已被 Git 忽略。归档保留 JSON、重新
渲染的 HTML 和后续分析交接文件；不会复制输入目录里的 HTML、执行文件、上传 PDF、调用
AMiner/模型接口或修改推送历史。引用、摘录与私人笔记留在本机，但这不是加密存储。

同一内容重复导入会复用同一归档；更改专题、文献、证据或笔记会生成新 ID。生成时间和检索
运行统计不参与内容哈希。已有归档遭到外部修改时拒绝覆盖；应从修正后的来源包新建归档。
导入验证身份、字段结构、证据归属和内容哈希，**不等于重新核验学术结论**。

## 2. 显式导出公开概览

```powershell
python -m src.research_archive publish-summary --id r_<实际16位哈希>
```

生成 `reports/research/<ID>.html` 和公开关联索引 `index.json`。公开内容仅包括专题标题、
论文题名、论文来源链接及 DOI/AMiner 身份映射，不包含摘录、对比表、全文文件名或私人笔记。
专题标题本身也会公开，导出前请确认可分享。

此命令只写本地文件。检查页面后，提交这两个文件并通过正常 GitHub Pages 工作流部署。
不要提交 `data/research-archive/`。仅归档不会触发发布，周报也不会读取私有归档。

后续周报会为身份匹配的文献显示最多三个专题概览链接。只用稳定 DOI/AMiner ID 关联；
没有这两种身份的 snapshot 文献可以归档，但不会凭相似标题自动关联。公开索引损坏、页面
缺失或被外部修改时省略链接，不阻断原周报。邮件继续使用原来的期刊摘要和对应周报链接。

## 3. 撤回概览

```powershell
python -m src.research_archive withdraw-summary --id r_<实际16位哈希>
```

撤回会从公开索引移除该条记录，把原 URL 页面换为撤回说明；再次提交并部署后生效。本地
完整证据包不变，后续生成的周报不再加链接。历史周报中已有的链接会进入撤回说明页。
这不能抹除 Git 历史、浏览器缓存或已经分发的副本。可用 `publish-summary` 重新导出。

写入期间使用独占 `.publish.lock` 防止并发发布互相覆盖；若进程异常终止留下锁，应先核实
没有其他发布进程，再由操作人处理锁文件。工具不会自行移除不属于自己的锁，也不会覆盖
被外部编辑的公开页面。

## 隔离验收

三个命令均支持 `--archive-dir` 和 `--public-dir` 指向任务专用目录，从而在不触碰生产
Pages 和本地正式归档的前提下，测试导入、导出、撤回、再次导出。关联代码没有网络依赖。
