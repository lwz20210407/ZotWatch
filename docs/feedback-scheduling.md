# 反馈参与检索调度

反馈现在不只出现在诊断里，也会影响 AMiner 有上限的推荐查询顺序。只使用仓库所有者的明确反馈，不把模型自己的评分当训练真值。

- 没有有效方向偏好时，维持原有轮换。
- 有有效偏好时，每轮第一个推荐位置仍按方向轮换，其余名额优先分配给明确正向反馈的方向。
- 轮换位置放在最前，避免重复推荐的提前停止把探索位长期饿死；短语搜索仍覆盖配置方向。
- 不自动改写用户的研究定义、材料要求或短语，不永久关闭低反馈方向，不扩大请求预算。
- `wrong_material / wrong_conditions / metadata_error / already_known` 表示该条结果或数据有问题，不用于推断用户不喜欢整个方向。原有针对该条文献的有界反馈调整保留。

每个查询记录稳定 ID、方向、返回数、主题通过数及报告选入数，多来源重复论文不会按行数重复计算。`selected_for_report` 仅表示进入生成的报告，不声称已经成功发送。实际交付仍由已有的历史提交机制管理。

本地 `data/cache/aminer/query-results.json` 保存最近一轮返回/主题通过观察；生成报告时，周报诊断补充报告选入数，并在折叠详情中展示查询效果表。缓存不包含反馈正文或凭据。

可以不联网预览下一批推荐方向：

```text
python -m src.query_feedback --output-dir <task-directory>
```

输出 `query-plan.json`，说明哪些名额来自轮换、哪些来自明确反馈及原因统计。此预览不会消耗 API 调用，也不会推进轮换游标。
