# 引文发现与可解释推荐

2026-09-17：每周运行已接入三个功能，不再只是一次性的引文网络审计。

## 运行路径

1. 同步 Zotero 后重建向量画像及同序号书目映射，避免月度缓存导致画像滞后。
2. 常规主题/期刊/作者候选去重、初排，选择至多 5 篇近期高相关论文作动态回溯起点。
3. `config/citations.yaml` 的 18 篇已核对种子通过 OpenAlex `cites` 查询追踪最近 30 天的后续论文。
4. 读取固定种子和动态起点的 `referenced_works`，仅回溯一跳；默认最多 400 篇参考文献候选。
   超额时优先多个起点共同引用的文献，余下部分按周轮换。单轮最多 40 个逻辑 API 请求，
   每请求最多尝试两次；每组前向查询最多 2 页、每页 100 条。接口失败和截断进入报告提示。
5. 对照 Zotero 文献库和跨轮推送历史去重。引用候选仍须通过力学主题筛选，绝不因引用了
   种子就无条件收录；不要求材料必须为 TC4。已有硬排除规则仍适用。
6. 将语义、现有排序和有界引文加分合并。近期论文进入综合推荐/作者动态；过期但相关的
   参考文献进入独立“经典文献补漏”，最多 5 篇，需达到 consider 阈值且语义相似度 >= 0.40。
   这个栏目名不意味着每篇都已被人工认定为开山经典。未来日期和缺日期记录不推送。

## 推荐依据

- 最近邻：真实 FAISS 索引位置对应的库内书目标题、DOI，不由语言模型编造。
- 正向关系：候选的参考文献中确实含有重点种子 ID。
- 反向关系：具体哪篇种子/本轮论文的参考文献包含该候选。
- 共享参考文献：与某个固定种子的交集至少 2 篇；重合度为
  `交集数 / sqrt(候选参考文献数 * 种子参考文献数)`，显示最多 5 个共同参考文献 ID。
- 引文加分上限 0.06：直接引用关系占其 2/3，归一化共享参考文献强度占其 1/3。
  这只是可调启发式，不是相关性概率；不是全网共被引分析，也不是全文阅读。

## 推送历史与失败语义

`data/watch-state/state.json` 仅记录规范 DOI/标识符和标题哈希及发送时间，不存储全文或密钥。
生成报告只写 `pending.json`。GitHub 使用 `--defer-history`，在 Pages 和邮件成功后才执行
`commit-history`，随后上传 `watch-state-v1` artifact。下一轮从最近 50 个 main 分支成功
运行中恢复最近一个未过期的历史文件，网络恢复失败直接失败，不悄悄清空历史。
Actions 交付串行运行，避免同一历史状态被两个运行同时消费。

artifact 保留 90 天。第一次上线、超过保留时间或历史被手动删除后，日志会明确警告可能
重复；历史无法追溯上线前已经发送的邮件。邮件成功但保存 artifact 失败时，下轮可能重发：
这是保守的至少一次交付，不承诺恰好一次。禁用定时任务超过 60 天的问题仍需单独处理，
这些功能不是 GitHub 仓库活跃度的永久豁免。

本地默认在报告/RSS生成成功后提交历史；若外部脚本还负责发信，应添加 `--defer-history`，
发信成功后执行 `python -m src.cli commit-history`。本地与 GitHub 历史相互独立。

## 数据覆盖与隐私

OpenAlex 引文缺失不等于论文没有参考文献。无 DOI、未收录、元数据匹配错误和缺摘要都会
限制召回。回溯不是无界爬取；共享参考文献只在已抓到候选与固定种子间计算。
公开 Pages 报告会显示推荐依据中的相似书目标题，不包含 Zotero 笔记或 PDF 全文。

依据：[OpenAlex 引文定义](https://help.openalex.org/data/works/citations/)、
[过滤与批量 ID 查询](https://help.openalex.org/api/filtering/)。

## 验证

`python -B -m unittest discover -s tests -v`：覆盖引用方向、日期、撤稿、请求上限、分页截断、
主题门控、来源合并、最近邻证据、评分、独立补漏栏目、HTML转义、RSS、历史暂存/提交和重复运行。
只读在线小规模验证：18/18种子解析，80篇回溯上限下发现102个去重候选，57个通过主题筛选；
其中30个有引用种子证据、45个有被起点引用证据，二者可重叠。不是最终推送数。
