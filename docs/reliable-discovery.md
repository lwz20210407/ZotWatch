# 可靠检索与分研究问题推荐

2026-09-17。只处理标题、摘要与引文元数据，不获取正文。本轮依据调研落地以下设计。

## 1. 限流、预算和检索检查点

此前云端确实出现HTTP 429后等待68413秒。现在 `Retry-After > 20秒` 会触发延后异常，
保留服务端要求的冷却时间；该来源暂停，其他来源继续。不会截短等待后重新请求。
冷却状态与成功GET响应写入 `data/network-state`，通过独立Actions cache跨运行恢复，
即使报告/邮件失败也尝试保存。已有成功页面可直接读缓存，不消耗新的网络请求。

`config/network.yaml` 默认：匿名OpenAlex本地估算上限0.08美元/UTC日；配置
`OPENALEX_API_KEY`后为0.8美元/日；每运行OpenAlex最多160次请求、Crossref180次。
这些是本地保护阈值，不是账户实时余额，不保证其他应用没有消费额度；不会购买额度。
API key只从环境/GitHub Secret读取，不写缓存、检查点或公开诊断。

179个主题查询保留，每来源每轮轮换40条；给引文和版本查询预留请求空间。
网络分页缓存48小时。查询轮换与成功页面缓存是有限检查点，不承诺对永久失败查询或
大范围分页结果穷尽恢复。轮换、截断、熔断均显示覆盖不足。缓存被GitHub清除后会重新抓取。
Workflow总时限50分钟，防止新的无限等待。预算和分页上限会影响召回，因此必须看覆盖提示。

## 2. 真正独立的语义候选入口

7个问题各有英语 `semantic_query`，直接调用OpenAlex `search.semantic`。不是把现有
候选重新命名为语义发现。关键词、期刊、作者、引文和语义通道合并去重，来源信息保留。
不要求语义候选必须与种子有引用联系，也不要求命中原有关键词组合；撤稿/硬排除仍适用，
最终再用本地画像相似度门槛控制相关性。

**实测接口限制**：当前语义端点拒绝 `from_publication_date`，只支持 `publication_year`
等部分过滤条件。程序按年份取每问题最多50条，再在本地判断日期。最近30天进入近期推荐；
超过窗口且相关、未见过的结果进入“跨圈方法发现（非近期新作）”，默认最多2篇。
这种接口上限会漏掉当年排名较后的近期论文，不宣称完整语义召回。

在线小规模验证：反演问题返回50个候选，本次其中0篇位于最近30天；此结果验证接口，不是
最终推荐数量或相关率。水泥等邻域结果仍需后续研究价值排序，不等于自动纳入博士主线。

## 3. 分问题画像与作用范围明确的反馈

每个方向独立构建规范化向量中心，记录样本数量与示例。初始化按标题摘要方向规则分组；
可在facet配置里指定 `collection_keys`（Zotero集合key）或 `seed_dois` 替代自动分组。
人工正反馈在对应画像中提升权重，负反馈仅移除对应方向的画像样本，不删除Zotero记录。

有问题画像时，语义评分部分为40%库内最近邻相似度＋60%最佳问题画像相似度；没有画像则
回退旧逻辑。报告的最近邻相似度仍保留原始值，不与画像分数混淆。分组是可配置初始画像，
并非经过逐篇人工确认的完美主题分类，需要用反馈和评估持续校准。

显式分问题反馈：

```powershell
python -m src.cli feedback --doi 10.1234/example --rating irrelevant --scope inverse --facets inverse
python -m src.cli feedback --doi 10.1234/example --rating reset --scope inverse
```

报告也提供对应问题的有用/不相关/撤销链接。`reset`作为持久撤销记录保留，避免旧Issue又把
反馈恢复。`later`、`reading`、`read`是中性阅读状态，不当作强正负标签；已读只影响普通推荐，
不会屏蔽更正/撤稿提醒。公开GitHub反馈仍只接收owner创建的合规数据块。

## 4. 周报的多样性与探索位

在前100个合格候选内，用分问题名额与语义冗余惩罚做贪心选择；主问题软上限约为总名额40%，
有余位且其他问题不足时放宽。最多预留2个名额给合格的低引用语义候选，不降低相关性门槛。
这不是“随机塞几篇”，也不是按材料一票否决。候选不足时不强行凑数。

## 5. 合作组合与局部关系图

在高相关观察记录中，稳定作者ID组合至少有2篇不同共同论文才展示，并要求至少一人已被关注。
超过12作者的论文不用于组合计算，限制大型署名列表制造虚假群体；输出最多5组。
只表示合作证据，不推断师生或正式课题组，不自动加入作者配置。

每篇推荐可展开最多5个邻居的SVG关系图。引用/被引用与标题摘要相似分别标注，虚线不代表引用。
不绘制4000节点的大图，不用中心性代替研究质量。

## 6. 离线评估，不凭感觉宣称提升

报告生成 `ranking-baseline.json` 和 `ranking-candidate.json`。前者是同一候选集上的旧语义
权重排序对照，不是完整旧版本回放；后者为新选择结果。准备独立人工标签后运行：

```powershell
python -m src.evaluate --labels my-labels.json --baseline reports/ranking-baseline.json --candidate reports/ranking-candidate.json --top 20
```

标签格式：`[{"doi":"10.1234/example","relevant":true}]`。
输出Precision@K、已标注部分准确率、标签覆盖率和相关研究问题覆盖。未标注不当负样本；
TopK未全部标注时Precision@K显示null。训练反馈与评估标签应分离。
目前没有人工评估集，因此**尚不声称推荐准确率已经提高**。

## 验证与依赖

自动测试包括长等待不sleep、冷却跨实例恢复、其他来源继续、缓存不含key、预算无网络拒绝、
查询轮换、画像分离、作用域反馈/撤销、中性待读、语义入口、去冗余、合著证据、缺标签评估。
不增加收费模型、商业账号或正文依赖。

接口参考：[OpenAlex语义检索](https://help.openalex.org/api/semantic-search/)、
[API成本说明](https://help.openalex.org/access/example-costs/)。具体过滤限制以本轮实际400响应和
修正后成功响应为准，不能只照搬文档中“多数过滤器可用”的泛化描述。
