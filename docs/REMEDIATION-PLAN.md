## 范围收缩决定（2026-09-19 用户拍板）

产品目标收回到一句话：
**每周自动发现与博士研究相关的新文献，过滤明显离题和重复，以简洁邮件提醒，并提供可追溯的网页详情。**

主流程只保留：`订阅来源 → 候选汇总 → 相关性筛选 → 去重排序 → 周报 → 发送记账`

两条硬约束：
1. **辅助功能失败不影响主流程**——翻译挂了发英文，某源挂了标注覆盖不足，任何分析不得拖住邮件
2. **没有证明有用的功能，默认关闭**——写好了不等于每周都跑、占版面、烧预算

| 决定 | 项 |
|---|---|
| **默认关闭**（代码保留，配置一行开回来） | 合作群体分析 `collaboration_groups` |
| **全保留，改成非阻塞** | 作者动向（含查漏补缺、新涌现）——用户明确要过，不因 Codex 建议降级 |
| 保留 | 局部证据网络图、`FeedbackModel`、迁移说明卡 |
| 正式推送时机 | **等第三批做完**再发 |

另：**研究链用来判断相关性，不强行做成 11 个互斥栏目**。一篇做好参数反演、损伤正则化
或屈服准则的论文本身就值得读，不要求覆盖整条链。这条直接决定 2.2 的做法。

## 总诊断

> 功能扩展速度超过了数据契约和验收体系的成熟速度。
> 系统可以执行成功、发出邮件、通过全部测试，同时使用过期向量、错误方向标签、
> 不完整译文，甚至把未完整交付的内容记为已送达。

这比那 22 个孤立 bug 更重要。反复出现的故障模式，每改一处都要对照自查：

1. 缓存命中被误当成内容一致
2. 来源命中被误当成相关性证明
3. 最相似方向被误当成事实分类
4. 一层修好了，旁路仍保留旧行为
5. 空结果同时代表成功、失败和截断
6. 展示修复没有同步修复底层语义
7. 交付成功与状态持久化被混为一谈
8. 测试工具复制业务逻辑，导致两者一起"自证正确"

## 最低验收门槛（全部要有测试，否则等于没修）

- [ ] 同版本改标题或摘要，必须触发正确的嵌入更新
- [ ] 完整快照删除一篇，画像和去重库同步移除它
- [ ] 任何本地回退都不能冒用远程 encoder 签名
- [ ] 所有奖励和反馈组合都满足实际声明的评分范围
- [ ] 非 TC4 论文可作为高价值方法论文，但不能被标成 TC4 材料事实
- [ ] 不同 DOI 的 Part I/II 不会因标题相似直接丢失
- [ ] 检索失败与成功空结果在状态上可区分
- [ ] 翻译空字段不视为完成，已交付内容有独立补译路径
- [ ] 限流熔断不能被拆批逻辑吞掉
- [ ] 多收件人的部分失败不能记成全体成功

**2.1 坑**：不能只把 `scoring.weights.author_bonus` 设 0——`config/authors.yaml`
`score_bonus: 0.03` 与 `config/citations.yaml` `score_bonus: 0.06` 是**另一条加分路径**，
在有界加权和倍率**之后**加回，反馈分再加减，没有最终钳制。

**2.2 结构性**：11 个 facet 混合了不同维度（TC4=材料对象、温度=载荷条件、断裂=现象、
反演=方法），天生不互斥，却被 argmax 当成互斥分类，再用于方向名称、多样性名额、
反馈作用域和主分数。"与某方向向量最接近"被错误升级为"确实属于该材料"。

**2.4 坑**：现有 `check_config` 只比较同 `match_fields` 下倍率递减，
**不能证明规则互不包含**。"读标题"是"读标题+摘要"的子集，不等于两个关键词规则之间存在包含关系。
