# 研究助手：标题、摘要与引文元数据版

2026-09-17。按用户确认：**不下载、解析或导入正文，也不调用收费大模型**。
本功能不声称完成全文精读；采用可解释规则和明确的人工反馈。

## 六项功能

| 功能 | 实现及边界 |
| --- | --- |
| 阅读反馈闭环 | 报告提供“直接有用、方法可迁移、机制参考、不相关、已读”按钮；打开预填的公开GitHub Issue，由用户提交。只接受 `config/research.yaml` 指定owner创建、结构校验通过的反馈；其他人的Issue及任意指令不执行。 |
| 问题覆盖诊断 | 7个研究方向分别统计抓取、主题通过、库内去重后、实际推送数；检索失败/分页截断时明确表示覆盖不完整，不能把零结果解释为没有新文献。统计本轮有限候选集，不是全网召回率。 |
| 方法迁移说明卡 | 根据摘要中的匹配语句列出候选用途、迁移前核查清单和简短证据；用途明确标注“规则推断”，不能直接迁移参数。缺摘要时降级为“仅题名”，不补写实验条件、结论或验证范围。 |
| 摘要方法作用线索 | 从摘要中明确提到的方法及同句的采用/改进/比较/局限词识别线索，处理常见否定表达。**这不是正文引用语境识别**，不把引用某论文等同于采用或反驳它；无法判断时保持未知。 |
| 新作者/种子候选 | 稳定OpenAlex作者ID至少出现在2篇不同高相关论文中才提出候选；相同论文重复运行不增加篇数。你明确认可的论文可提出固定种子候选。报告列出代表作，**不自动改写作者/种子配置**。 |
| 版本与更正提醒 | 对固定种子和推送论文的DOI轮换检查Crossref版本关联、明确的update-to更正/撤稿，以及OpenAlex撤稿标记。提醒独立于普通文献去重/已读状态；同一事件成功交付后不再提醒。 |

## 反馈使用

报告中的反馈按钮只打开GitHub Issue填写页面，不会替用户提交。
**仓库和Issue是公开的，不要附上私人笔记或未公开研究内容。** 每次运行读取最近100个更新
的Issue，之前接受的反馈保存在交付历史中。只解析固定JSON数据块，不执行Issue里的指令。

也可显式在本地记录：

```powershell
python -m src.cli feedback --doi 10.1234/example --rating transferable --facets inverse regularization
```

该命令写入 `config/feedback.yaml`；本地改动提交并推送后才会用于GitHub运行。
本地配置优先于Issue。多个Issue对同一DOI的反馈，以最近更新时间为准。
“已读”只屏蔽普通推荐，不训练负偏好，也不屏蔽出版更新提醒。

反馈仅学习 `stress_state / thermorate / fracture / inverse / regularization / impact /
microstructure` 方法方向，不直接按钛、铝、钢加减分。每个方向加入两个中性伪样本平滑，
单篇评分调整上限默认±0.08；不相关反馈是降权，不是材料级一票否决。
全局关闭开关及阈值在 `config/research.yaml`。

## 证据和候选确认

摘要中“采用某模型”仍可能是在描述对比模型而非最终模型，因此输出为**规则线索**而非事实断言。
多个作用词同句则同时展示；每篇最多2张方法卡、2条摘要线索，引用片段共用小额文本预算。

作者候选按ID而非同名字符串统计；作者ID本身也可能有消歧错误，因此需核对代表作和机构。
大于30作者的论文不用于作者候选计数。研究观察最多保留最近500篇不同论文，不按重复周数
膨胀证据。确认后再修改 `config/authors.yaml` 或 `config/citations.yaml`；本功能不自动批准。

## 更新检查与状态

每轮默认检查10个DOI，优先最久未尝试的条目；失败也轮换，避免永久占用队列。
每个DOI最多两类Crossref请求（元数据、updates），另有一批OpenAlex状态查询；每个请求
最多两次尝试。更新通知超过20条会提示截断。未收录/缺关系/接口失败均不能证明没有更新。
不会仅凭相似标题猜测预印本与正式论文的关系；依赖明确DOI关系。

出版事件显示的是**系统发现日期**，不冒充事件发生日期。首次检查可能发现旧的更正/撤稿。
Crossref的正式通知优先，OpenAlex单独标记则提示进一步核对；不对相关作者整体降权。
预印本→正式版仅在明确登记关联时通知，不代表所有数据库都能完整提供此信息。

所有新增状态（反馈、覆盖记录、研究观察、出版事件）与普通推送历史共同暂存，只有Pages及
邮件成功后才提交至90天保留的artifact。失败重试保守采用至少一次交付语义。
本地与GitHub状态独立；首次启用没有上线前的完整推送记录。

机器可读诊断随报告生成 `reports/research-diagnostics.json`，包含覆盖数字、候选名单和
去敏后的警告，不包含完整反馈Issue或密钥。抓取警告中的URL和参数不会原样发布。

## 接口依据

[Crossref过滤说明](https://www.crossref.org/documentation/retrieve-metadata/rest-api/rest-api-filters/)
定义 `updates`、`relation.object`、`update-type` 等过滤条件。程序进一步核验通知中的
`update-to.DOI`，而不是仅靠标题猜测更正对象。

## 验证范围

自动测试覆盖owner限定、恶意/非法反馈拒绝、分数上限、材料无关的方法偏好、已读行为、
覆盖故障区分、摘要否定线索、无摘要降级、候选按不同论文计数、版本关联方向、更新突破
普通去重、事件一次交付、失败轮换、HTML转义及整条报告/历史流程。
只读在线验证以此前已审计的撤稿DOI检查，得到Crossref明确关联的撤稿和勘误通知，未获取正文。
